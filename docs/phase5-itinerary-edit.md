# Phase 5 — 行程編輯（Done / Cancel）

## 最新使用者決策

不自動儲存，沿用 Thailand_Itinerary 的 Edit / Done / Cancel。輸入、失焦、新增、刪除、拖曳與編輯模式中的日期切換全部只更新本機 React 草稿。Done 才發出 PUT；Cancel 還原進入編輯時的資料。重新載入／離開編輯中的頁面會顯示瀏覽器未儲存提示。

沒有加入共享密碼，Google 原生權限仍由後端驗證。dnd-kit 使用拖曳手把、PointerSensor（滑鼠／觸控）與 KeyboardSensor，輸入欄不當作拖曳啟動區。uiKey 只在畫面中識別草稿，不送往後端或寫入工作表。

## 後端流程

- GET access：目前使用者自己的 OAuth 查 Drive capabilities.canEdit，公開訪客不會看到可用的 Edit。
- GET itinerary：先以無 OAuth 的公開讀取確認旅行可公開查看，再以目前使用者的 OAuth 檢查 canEdit，讀取最新 Itinerary 原始格值，建立內容版本摘要。
- PUT itinerary：同源驗證、Session、輸入格式及大小驗證；重新檢查 canEdit、重新讀取並比對版本。有修改衝突則 409，不直接覆蓋。
- 日期穩定排序，同日保留草稿順序。一次 batchUpdate 寫入 Date / Activity / MapURL 三欄，並清除多餘舊尾列。必要時在同一批次先擴充列數；不覆蓋格式或其他欄位。
- 日期、活動與連結皆以 stringValue 寫入，不將 = 開頭文字當公式。已存在的真實公式會阻止編輯，避免靜默轉成純文字。
- 寫入後重新讀取確認。只有結果一致才回成功。若前次成功但 HTTP 回應遺失，重試 Done 發現預期結果已完整存在時直接確認，不重複寫入。

衝突及撤權會鎖住編輯、保留畫面草稿，提供複製草稿，以及明確標示放棄草稿並重新載入的操作。暫時網路失敗可重試 Done。刪除空白新活動不會寫入空白行程。

## 並行限制

本機程序使用每份 Spreadsheet 的短期鎖，避免同一程序中的網站 PUT 同時儲存，不建立旅行資料庫。但 Google Sheets 不支援本流程需要的條件式讀取／比較／寫入交易；直接在 Sheets 修改者不受本機鎖約束，比對後至寫入前仍有競態。寫後驗證也不能找回已被覆寫的修改，不能宣稱絕對零遺失更新。此限制已在實作期間向使用者說明。

## Google 授權範圍

維持 drive.file，不擅自擴大 Google scope。對應檔案必須在目前使用者及此 OAuth 應用程式的可存取範圍內；Google 最終決定存取及編輯權限。本機原建立者已驗證 canEdit 與編輯快照成功。另一個編輯者帳號仍需實際測試，不把擁有原生 Editor 角色視為一定已完成 app 檔案授權。若 Google 阻擋，需再釐清最小可行授權流程，不能改用擁有者 Token 代寫。

## 驗證

50 項自動測試通過，包括前階段與新增的快照不寫入、同日穩定排序／重複活動、遠端修改衝突、權限撤銷、尾列清除、擴列批次更新、失敗／重試、寫後驗證及純文字儲存。

真實瀏覽器測試：

- 原建立者的 Edit 按鈕正確顯示，進入編輯可見 Done / Cancel。
- 新增兩筆測試草稿、輸入活動、鍵盤操作手把調整順序。
- 在按 Done 之前，以無登入 Cookie 的公開讀取確認 Sheets 行程仍為 0 筆。
- 點 Cancel 後，畫面回復空行程，未寫入任何測試資料。

尚待使用者／後續驗證：真實 Done 寫入、其他 Google 帳號的讀寫／撤權、手機實機觸控與寫入失敗的真實網路情境。自動測試涵蓋模擬失敗，不當作真實 Google 端對端測試通過。
